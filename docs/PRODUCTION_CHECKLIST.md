# 실서비스 전환 체크리스트

지금 상태(해커톤/데모 프로토타입)에서 실제로 돈이 오가는 서비스로 가려면
넘어야 할 벽들. 체크박스는 "이 프로젝트 안에서 해결 가능한가"를 기준으로
분류했다 — 법무/제휴처럼 코드로 못 푸는 것도 명시적으로 남겨둔다.

## 1. 법적/컴플라이언스 (코드로 못 풂 — 별도 검토 필요)

- [ ] **전자금융거래법**: 실제 이체를 대행/중개하려면 전자금융업 등록 또는
      은행과의 제휴 구조가 필요. 지금은 완전 모의 이체라 해당 없음.
- [ ] **개인정보보호법 — 생체·행동 정보**: 터치 패턴·가속도계 데이터는
      "행동 생체정보"로 분류될 수 있다. 수집 목적 명시, 별도 동의, 보관
      기간, 파기 절차가 법적으로 요구됨(`LIMITATIONS.md` #9와 연결).
- [ ] **약관/개인정보처리방침**: 지금 앱에 아예 없음.
- [ ] 법무 검토 없이는 실사용자 데이터를 실제로 모으면 안 됨 — 지금까지의
      수집은 전부 팀 내부/동의한 참여자 대상으로 한정해야 함(이미 그렇게
      하고 있음, 계속 유지).

## 2. 은행 연동 (코드로 못 풂 — 제휴/API 필요)

- [ ] 지금은 `server/public/index.html`의 완전 모의 이체 화면. 실제
      계좌 조회·이체 실행은 오픈뱅킹 API 또는 은행 코어뱅킹 연동이 필요.
- [ ] PRESENCE의 역할은 "이체 실행 전 위험도 판정"이지 이체 자체가 아님 —
      실제로는 은행/PG사의 이체 승인 파이프라인에 훅으로 꽂혀야 함
      (`/api/session/decision`의 `requireChallenge`/`band`를 그 파이프라인이
      소비하는 구조).

## 3. 보안 운영 (이 프로젝트 안에서 지금 당장 해결 가능)

- [ ] **서명 키**: `server/src/sign.js`가 `PRESENCE_SIGNING_SECRET` 환경변수가
      없으면 개발용 기본값(`dev-only-insecure-secret-...`)을 쓴다. 실배포
      전 반드시 실제 비밀 관리 시스템(AWS Secrets Manager, Vercel 환경변수
      등)에서 주입하고, 기본값 fallback 자체를 프로덕션 빌드에서 제거할 것.
- [ ] **인증/권한**: 지금 API는 전부 인증 없이 열려 있음(`/api/session/export`,
      `/api/l2/check` 등). 실서비스에서는 세션/사용자 인증, rate limiting,
      요청 출처 검증이 필요.
- [ ] **HTTPS 강제**: 로컬/데모는 http도 허용하지만 실배포는 HTTPS만.
- [ ] **의존성 취약점 점검**: `npm audit` 정기 실행, Playwright/Express 등
      버전 고정 및 보안 패치 추적.
- [ ] **로그·모니터링**: 지금은 콘솔 로그뿐. 실서비스는 위험도 판정 이력,
      오탐/미탐 신고, 에러율에 대한 알림 체계가 필요.

## 4. 데이터 거버넌스 (이 프로젝트 안에서 지금 당장 해결 가능)

- [ ] `server/data/sessions/`가 인증 없는 로컬 파일 저장소 — 실서비스는
      암호화된 DB + 접근 제어로 교체.
- [ ] 보관 기간 정책 수립 및 자동 파기 배치.
- [ ] 수집 동의 UI 추가 (지금 개발자 도구의 수집 화면엔 동의 절차가 없음).
- [ ] 참여자 재식별 방지 — 지금 `participant` 필드가 평문 자유 입력이라
      실명 등을 넣지 않도록 안내 문구 추가.

## 5. 검증 완료 게이트 (실서비스 전 반드시 통과해야 하는 실측 항목)

지금 알려진 미검증 항목들 — `LIMITATIONS.md`에 이미 기록돼 있지만, 이게
바로 "실서비스로 가기 전 반드시 실측으로 닫아야 하는" 목록이다:

- [ ] L3 융합 가중치를 실제 정상 데이터로 학습 (지금 손으로 튜닝한 기본값)
- [ ] L3 원격조작 조건 데이터 확보 — 정상 vs 원격 ablation을 실제로 돌려서
      FPR@TPR95 숫자를 내야 함 (지금은 0건)
- [ ] iOS 실기기에서 자동보정·상대 임계값 수렴 검증
- [ ] Vercel(또는 실제 배포 인프라)에서 L2 라이브 검증
- [ ] 거치대/차량 거치 등 "정지된 정상 사용"에 대한 실제 오탐률 측정
- [ ] IMU 위조(스푸핑) 저항성 — **이건 이 프로젝트 코드만으로는 못 닫는다.**
      네이티브 SDK 레벨 attestation(Play Integrity API 등, `docs/
      NATIVE_APP_ROADMAP.md` 참고)이 나오기 전까지는 "레이어를 늘려 공격
      비용을 올린다"가 최선이고, 그 사실을 사용자/판사에게 숨기지 말 것.

## 6. 우선순위 제안

법적 검토(1번)와 은행 연동(2번)은 시간이 오래 걸리고 이 팀 단독으로 못
끝내는 일이라, **지금 당장 실서비스 착수를 목표로 하지 않는다면** 3~5번
(보안 운영, 데이터 거버넌스, 검증 게이트)부터 순서대로 닫아가는 게 맞다.
이 세 카테고리는 전부 이 프로젝트 안에서, 지금 있는 도구(수집 화면, 학습
파이프라인, 평가 스크립트)로 실제로 진행할 수 있는 일들이다.
